# Contact And Support

## Public Questions And Bugs

Use the issue tracker that owns the affected surface:

- artifacts, packages, manifests, checksums, and release notes:
  [coakka-publish issues](https://github.com/phuong-tran/coakka-publish/issues)
- samples, walkthroughs, and sample integration behavior:
  [coakka-samples issues](https://github.com/phuong-tran/coakka-samples/issues)

Include the affected version or generation, operating system and architecture,
artifact or sample path, reproduction steps, expected result, and actual
result. Do not attach credentials, private keys, access tokens, customer data,
or confidential logs to a public issue.

## Direct Contact

For general support, release coordination, sensitive integration details, or
questions that should not begin publicly, contact:

- `gabrielgun1983@gmail.com`

## Security Reports

Do not open a public issue first for a suspected vulnerability, leaked secret,
artifact-integrity problem, or misleading security default. Use the repository
private security reporting flow when available, or email
`gabrielgun1983@gmail.com` and clearly mark the message as a security report.

Include the affected artifact or package identity, digest when relevant,
reproduction, impact, and whether the issue may span source, publish, and
sample repositories. Remove secrets and customer data unless a secure exchange
method has been agreed.

For common diagnostic steps, see [Troubleshooting](troubleshooting.md).
